# Клоп

Общие списки дел и покупок. Без регистрации: никнейм хранится в браузере и используется как ID пользователя. Одинаковый никнейм на разных устройствах означает одного пользователя. Все, у кого есть скрытая ссылка, видят и могут редактировать все списки.

## Запуск через Docker

```bash
docker compose up -d --build
docker compose logs klop
```

В журнале будет ссылка вида `http://localhost:8080/<случайный-путь>/`. Откройте её в браузере. Путь генерируется один раз и сохраняется в томе с данными, поэтому перезапуск его не меняет. В корне сайта и вне этого пути сервер возвращает 404. API и файлы интерфейса тоже доступны только под скрытым путём.

По умолчанию порт доступен только на сервере (`127.0.0.1`). Чтобы подключаться с других устройств, скопируйте `.env.example` в `.env`, укажите `BIND_ADDRESS=0.0.0.0` и перезапустите `docker compose up -d`. В ссылке замените `localhost` на адрес сервера. Для размещения за HTTPS-прокси можно оставить привязку к `127.0.0.1`; прокси должен передавать исходный путь целиком. Внешних шрифтов, аналитики и CDN нет.

Необязательный `APP_PATH` в `.env` задаёт свой скрытый путь: 16–128 латинских букв, цифр, дефисов или подчёркиваний, без `/`. Ссылка даёт полный доступ к общему пространству: передавайте её только своим пользователям. Для доступа через интернет используйте HTTPS, чтобы ссылка и данные передавались в зашифрованном виде.

## CI и образы в GHCR

При каждом пуше в `main` workflow `.github/workflows/publish.yml` проверяет Compose и скрипт развёртывания, запускает тесты и затем собирает образ для `linux/amd64` и `linux/arm64`. Успешная сборка публикуется как:

```text
ghcr.io/owner/repository:latest
ghcr.io/owner/repository:sha-<полный SHA коммита>
```

`owner/repository` берётся из GitHub-репозитория автоматически и приводится к нижнему регистру. Публикация использует встроенный `GITHUB_TOKEN` с `packages: write`; отдельный секрет для CI не нужен. В репозитории должны быть разрешены GitHub Actions и публикация пакетов. Образ связывается с репозиторием через OCI-метку `org.opencontainers.image.source`.

## Развёртывание готового образа на сервере

Нужны Docker, Compose v2 с поддержкой `up --wait` и `flock` (util-linux). На сервере достаточно файлов `scripts/deploy.sh`, `compose.ghcr.yaml` и `.env` с той же структурой каталогов; можно также использовать полный checkout проекта.

В `.env` укажите реальное имя своего образа (вместо `owner/repository`):

```dotenv
KLOP_IMAGE=ghcr.io/owner/repository:latest
PORT=8080
BIND_ADDRESS=0.0.0.0
# APP_PATH=ваш-существующий-скрытый-путь
```

Если образ приватный, один раз выполните под тем же пользователем, который будет запускать скрипт:

```bash
docker login ghcr.io --username YOUR_GITHUB_LOGIN
```

В запрос пароля введите GitHub personal access token (classic) с `read:packages` и доступом к пакету. Для публичного образа вход не нужен. Токен в `.env` приложения не записывается.

Запуск и последующие обновления выполняются одной командой из любого каталога:

```bash
/opt/klop/scripts/deploy.sh
```

Замените `/opt/klop` на каталог проекта на сервере. Можно разово передать другой образ: `./scripts/deploy.sh ghcr.io/owner/repository:sha-<SHA>`. Он применяется только к этому запуску; автоматические обновления продолжают использовать `KLOP_IMAGE` из `.env`.

Скрипт скачивает образ перед обновлением контейнера и ожидает успешной проверки HTTP и SQLite до 120 секунд. Если скачать образ не удалось, работающий контейнер остаётся на месте. Если проверка запуска не прошла, скрипт завершится с ошибкой; автоматического отката нет. Том с данными не удаляется, локальная сборка не запускается. Одновременные запуски защищены файловой блокировкой.

Для обновления каждые 5 минут добавьте в `crontab -e` того же пользователя:

```cron
*/5 * * * * /opt/klop/scripts/deploy.sh >> /opt/klop/deploy.log 2>&1
```

Скрипт всегда проверяет актуальный `latest`, а Compose пересоздаёт контейнер, когда образ изменился. Серверу не нужен `git pull` для обновления приложения; при изменении самой конфигурации развёртывания обновите скрипт и Compose-файл отдельно.

При переходе с локальной сборки запускайте скрипт **в том же каталоге проекта**, с прежним `.env` и прежним `COMPOSE_PROJECT_NAME`, если он был задан: тогда используется существующий том с данными и скрытым путём. Для отдельного файла окружения доступна переменная `KLOP_ENV_FILE=/абсолютный/путь/production.env`.

Посмотреть состояние и скрытую ссылку (если изменили `PORT`, подставьте его в ссылку):

```bash
docker compose -f compose.ghcr.yaml ps
docker compose -f compose.ghcr.yaml logs klop
```

Справка: [публикация образов из GitHub Actions](https://docs.github.com/en/actions/tutorials/publish-packages/publish-docker-images), [доступ к GHCR](https://docs.github.com/en/packages/working-with-a-github-packages-registry/working-with-the-container-registry).

## Запуск без Docker

Нужен Python 3.12 или новее, дополнительные пакеты не требуются.

```bash
python3 server.py
```

Откройте ссылку из терминала. Данные будут в `data/`. Переменные окружения: `HOST` (по умолчанию `0.0.0.0`), `PORT` (`8080`), `DATA_DIR`, `APP_PATH`. Файл `.env` автоматически читает только Docker Compose.

## Использование

- При первом входе задайте никнейм. Изменить его можно нажатием на профиль.
- Новый список всегда создаётся без группы. В настройках списка можно назначить любое количество групп, изменить название, тип и действие при выполнении пункта.
- Доступны простые списки, списки с категориями и упорядоченные списки. Порядок меняется стрелками. Текст пункта редактируется прямо в списке и сохраняется при уходе из поля.
- Выполнение пункта зачеркивает его, переносит в корзину или удаляет навсегда — в зависимости от настройки списка. Удаление навсегда требует подтверждения. Зачеркнутый пункт можно вернуть повторным нажатием.
- Корзина — отдельная скрытая из обычного просмотра группа для списков и пунктов. Удаление группы сохраняет списки. Удаление категории сохраняет пункты без категории.
- В меню доступны плитка, список и фильтры по группам. Данные с других устройств обновляются каждые 4 секунды, когда вы не вводите текст. Конфликтующие изменения одного списка отклоняются с сообщением; повторите действие после обновления.
- Экспорт одного списка — кнопка скачивания в открытом списке. Экспорт всего и импорт — в боковом меню (на телефоне над заголовком). JSON содержит группы, категории, порядок, выполненные пункты и корзину. Импорт **добавляет копии** списков с новыми ID, не заменяя существующие; группы с одинаковым именем объединяются. Максимальный размер запроса импорта — 5 МБ. Формат: `format: "klop"`, `schemaVersion: 1`.

SQLite хранится в Docker-томе `klop-data` либо в `DATA_DIR`. Автоматического резервного копирования нет. `docker compose down` сохраняет данные; команда с `-v` удаляет том и все данные.
